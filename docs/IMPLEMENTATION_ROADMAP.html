ZAK MCP Gateway: Implementation Roadmap

System Architecture, Execution Lifecycle & Phase-Wise Implementation Plan

1. Executive Overview

The ZAK MCP Gateway (TO-MCP) is a transparent middleware proxy positioned between AI agents (Cursor, Claude Desktop, LangChain) and downstream Model Context Protocol servers. It resolves the two critical protocol flaws: Schema Inflation and Payload Flooding.

❌ Standard MCP (Without Gateway)
  • Fixed cold-start: ~28,500 tokens of unminified Draft-07 JSON schemas.
  • Unused tools: 91% of loaded tools are never called during a session.
  • Payload flood: 15KB–60KB raw REST API payloads injected into memory.
✅ ZAK MCP Gateway (Optimized)
  • Fixed cold-start: ~320 tokens (exposes only 2 universal meta-tools).
  • On-demand discovery: Compact TypeScript signatures loaded JIT.
  • Egress projection: JSONPath masks strip nulls and unwanted fields.

2. Three-Step Execution Lifecycle

Step 1: Just-In-Time Discovery (mcp_search_tools)
Agent sends a query (e.g. "create issue"). MiniSearch BM25 engine retrieves matching tools in <1ms and returns compact TypeScript signatures (~36 tokens vs ~192 tokens JSON schema).
Step 2: Execution Dispatch & Decision Gate (mcp_call_tool)
Gateway evaluates Tier-1 SHA-256 exact hit cache. If idempotent query is cached, returns result instantly (0 tokens, 0 latency). Otherwise, dispatches call to child MCP process.
Step 3: Egress Distillation & Projection (project_fields)
Gateway applies JSONPath field whitelisting, removes recursive null/empty structures, and transforms JSON arrays into compact TSV tables before returning to the model.
