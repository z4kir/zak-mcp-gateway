ZAK MCP Gateway v0.4.2

15 Nov 2026 · Robust start-up

Fixes found by testing the new agent skill in Claude Code: a slow server no longer makes the agent drop the gateway, and setup gets a check command. No change to how tokens are saved.

In one picture: The concierge opens the desk on time even if one back office is still unlocking its door; requests for that office simply wait for it.

What's new

FeatureWhat it does (simply)Where to switch it
Answer on timeThe gateway waits at most startupWaitMs (15 s) for the servers before answering the agent's handshake. Slower servers keep connecting in the background, the instructions name them as still starting, and calls wait only for the server they need.gateway.startupWaitMs
check commandStarts every server once, prints one line per server (ok with its tool count, or FAILED with the reason) and the tool-definition tokens, then exits with code 1 if a server failed.zak-mcp-gateway check
Better init defaultsinit adds the GitHub noise keys and default fields from the example config, so big issue lists come back as a readable table instead of one raw row.zak-mcp-gateway init
Clean shutdownThe gateway exits when the agent closes its input, even during start-up, and closing it also stops servers that are still starting.built in
Agent skillskills/zak-mcp-gateway: SKILL.md for Claude Code, Cursor and Antigravity, with a configuration reference and a benchmark; skills/pack.mjs builds the marketplace zip.skills/

ProblemResult

Notes

  • Run zak-mcp-gateway check once after changing servers.json; it also fills the npx cache, so the agent's starts are faster.
